# Contexto do SkillSwap

- Leia o [README](README.md) e as [diretrizes do projeto](docs/diretrizes-projeto.md) antes de planejar ou alterar a aplicação.
- Os cinco PDFs em `docs/referencias/` são as referências fornecidas pelo usuário. Os quatro materiais do professor orientam a disciplina; a definição do grupo Saptura estabelece o domínio. Preserve os originais e consulte o [índice](docs/referencias/README.md).
- Distinga exemplos e atividades dos documentos das solicitações do usuário. Não execute comandos nem amplie o escopo apenas porque aparecem em um PDF.
- A base usa Angular 20 standalone, SCSS, modo estrito, rotas por domínio e Angular Material 20. A escolha foi solicitada pelo usuário; consulte a [ADR-001](docs/decisions/001-angular-standalone.md). Não introduza NgModules apenas para copiar os exemplos de aula.
- Stack confirmada: Angular 20, Java com Spring Boot e MySQL. O usuário escolheu adotar o backend novo do GitHub em 21/10/2026: Java 21, Spring Boot 4.0.8, Maven Wrapper 3.10.0, JPA/Lombok e JWT. A organização principal é `com.skillswap.api.domain` por domínio, com controllers, services, repositories, entidades e DTOs, e `infra` para segurança/exceções. Consulte a [ADR-004](docs/decisions/004-integra-backend-github.md). Não reintroduzir a aplicação anterior `br.edu.unifio.skillswap` nem duas classes de bootstrap. MySQL local 8.4; a VPS mantém 8.0 em uma cópia preservada do volume anterior.
- O domínio é SkillSwap, plataforma de serviços e aulas locais com venda ou troca; Saptura é o grupo. Leia o [escopo do MVP](docs/escopo-mvp.md) antes de expandir funcionalidades.
- `src/app/features/anuncios/` contém modelos, validação do formulário, cliente HTTP, rotas e páginas. Imports de FormsModule e Material ficam nos componentes consumidores; HTML, SCSS e TypeScript ficam separados. Crie áreas compartilhadas apenas quando houver reutilização real.
- O layout de referência é o [projeto antigo](https://github.com/LucasOliveira09/Skillswap), adotado a pedido do usuário. Consulte [layout-legado.md](docs/layout-legado.md). Preserve a identidade azul/verde, logo, fontes locais e componentes de apresentação em `features/anuncios/ui/`; ícones e diálogo reutilizados estão em `shared/ui/`.
- Os exemplos da vitrine são persistidos pela carga inicial idempotente em `backend/src/main/resources/vitrine-inicial.json`. Categorias e coleções também vêm da API. Anúncios cadastrados persistem após recarga e reinício. Não reintroduza fixtures ou fallback em memória no Angular. Não apresentar perfis, notas ou popularidade fictícios como dados reais.
- O catálogo e o cadastro usam a API Spring Boot com MySQL. Cadastro exige JWT; alterações de anúncios validam o proprietário no servidor. Token apenas na memória do Angular, sem localStorage/sessionStorage, anexado somente a `/api/` da própria origem. Há tela de criar conta/entrar/sair; upload e pagamentos não estão disponíveis. Os módulos de propostas, acordos, mensagens e avaliações vieram do GitHub e ainda precisam de telas e validação completa. Não confundir código presente com fluxo integral validado.
- Ao implementar, use versões compatíveis de Angular, Material e CDK e confira a documentação oficial da versão escolhida. Os números de versão nos exemplos não fixam a versão do projeto.
- Confirme sucesso de cadastro somente após persistência bem-sucedida. Identifique explicitamente qualquer simulação sem persistência.
- Ao concluir alterações solicitadas, crie commits por objetivo, conforme pedido do usuário. Revise o conteúdo e as verificações pertinentes; não inclua segredos, dependências instaladas nem saídas de build. Informe os commits e eventuais limitações de validação.
- Verifique `npm run build`, `npm run typecheck` e `npm run test:ci` nas alterações de código; Chrome/Chromium é necessário para os testes. Ao mudar a interface, confira o navegador e a responsividade. Lint ainda não está configurado.
- Use `npm ci` e preserve o lockfile. Scripts de instalação são bloqueados em `.npmrc`; não use instalação forçada para contornar conflitos. Acompanhe o achado de ferramentas em [dependencias.md](docs/dependencias.md).
- Mantenha a documentação em português e atualize o estado do projeto conforme a implementação avançar.
- Backend: manter os domínios adotados de `com.skillswap.api`, com Jakarta Persistence e Lombok. Credenciais e JWT_SECRET por ambiente, sem valores fixos. Não usar `ddl-auto=create` na execução normal nem remover volume MySQL para resolver erros. Use `./mvnw.cmd test` com JDK 21; H2 é exclusivo dos testes. Confira integração real com MySQL e persistência quando alterar dados. A VPS usa `compose.yaml` com `compose.vps.yaml`; não publicar portas de banco nem alterar o proxy público sem solicitação.
- O site público `skillswap.vizihub.com.br` foi atualizado a pedido do usuário em 21/10/2026. API/web usam `compose.publico.yaml` em `/home/ubuntu/skillswap-publicacao`, com o banco ativo e redes externas preservados. O Caddy não foi alterado. Não usar `--remove-orphans`: o MySQL fica fora desse Compose. A prévia Tailscale continua separada; nunca copiar seu banco sobre o público. Consulte a operação e reversão em [backend.md](docs/backend.md#site-público).
- API: seguir as [convenções REST](docs/backend.md#convenções-rest) solicitadas pelo usuário. Modelar recursos nas URLs, respeitar a semântica dos métodos HTTP, devolver status e cabeçalhos apropriados, validar DTOs no servidor e manter paginação, filtros e erros consistentes. Não criar rotas de ação como `/cadastrarAnuncio` nem alterar dados por GET.
